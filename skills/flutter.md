# Flutter

## 目标边界

能独立设计、开发、调试、构建和发布常规 Flutter 项目；能够区分 Dart、Flutter 框架、插件和 Android/iOS 平台问题，并审查、修改和排查 AI 生成的代码。

近期不要求达到 Flutter Framework、Engine 或图形渲染专家水平，但不能以“页面可以运行”代替对状态、生命周期、异步、构建和平台桥接的理解。

## 教学与实战关系

核心能力不能由综合项目替代。每个领域都按以下门禁推进：

```text
L0 概念与 Android/Kotlin 对照
→ L1 可运行的受控实验
→ L2 只给现象的半开放任务
→ L3 综合业务或真实故障
```

每章统一包含：

1. L0：目标、概念地图、Android/Kotlin 对照与适用边界；
2. L1：带注释的最小代码、关键执行链和受控实验；
3. L2：只给现象与验收条件的半开放修改或故障任务；
4. L3：主项目综合业务或真实故障迁移；
5. 测试、日志、截图、构建产物或性能数据；
6. 是否允许进入下一章的结论。

测试、日志、静态分析、依赖治理、安全、隐私、适配和可访问性是横切门禁，从首次出现相关代码时开始执行，不集中推迟到 08。

## 中级验收

只有同时满足以下条件，才能将 Flutter 更新为“中级独立开发”：

- 能脱离整页生成完成登录、列表、详情、上传等常规模块；
- 能解释现代 Dart 数据建模、Widget、Element、状态、生命周期和异步更新链路；
- 能完成表单输入、响应式布局、基础国际化和无障碍检查；
- 能设计清晰的不可变状态流、导航、模块边界和依赖方向；
- 能处理鉴权会话、网络、缓存、权限、敏感数据和平台隐私的常见问题；
- 能使用静态分析、日志、自动化测试、Crash 记录和 DevTools 提供问题定位证据；
- 至少完成一次 Android/iOS 双端原生桥接和一次双端 Release 发布演练；
- 能追溯构建版本、依赖、产物和符号文件，并说明灰度或回滚路径；
- 每个领域都有代码、测试、日志、截图、构建产物或案例中的至少一种证据；
- 能审查、解释并局部重写 AI 生成代码。
