# Flutter

## 目标边界

能独立设计、开发、调试、构建和发布常规 Flutter 项目；能够区分 Dart、Flutter 框架、插件和 Android/iOS 平台问题，并审查、修改和排查 AI 生成的代码。

近期不要求达到 Flutter Framework、Engine 或图形渲染专家水平，但不能以“页面可以运行”代替对状态、生命周期、异步、构建和平台桥接的理解。

## 教学与实战关系

核心能力不能由综合项目替代。每个领域都按以下门禁推进：

```text
L0 概念与 Android/Kotlin 对照
→ L1 可运行的受控实验
→ L2 只给现象的半开放任务
→ L3 综合业务或真实故障
```

每章统一包含：

1. 本章目标与前置知识；
2. 核心概念地图；
3. Android/Kotlin 对照；
4. 带注释的最小代码与关键执行链；
5. 可运行的引导实验；
6. 常见错误和一个故意制造的故障；
7. 验收问题、代码交付物与证据；
8. 是否允许进入下一章的结论。

## 学习与实战顺序

```text
01 Dart 核心基础
→ 02 Widget、布局与渲染
→ 03 状态与工程组织
→ 登录垂直切片
→ 04 网络与数据
→ 列表、分页、详情、缓存与 SSE
→ 05 图片、文件与权限
→ 图片选择与上传
→ 06 双端构建与发布
→ 07 Platform Channel 与原生桥接
→ 08 性能、日志、测试与故障排查
→ Flutter 中级独立验收
```

实战不是独立课程，而是用于证明相邻核心能力已经能够迁移到业务：

| 实战 | 主要验收领域 |
|---|---|
| 登录与表单状态 | 01、02、03 |
| 列表、分页、详情、缓存、SSE | 04，并复用 01～03 |
| 图片选择与上传 | 05，并复用 04 |
| Android/iOS Release 构建 | 06 |
| Android 原生能力与事件流 | 07 |
| 性能分析、日志、测试与故障修复 | 08，并综合全部领域 |

## 中级验收

只有同时满足以下条件，才能将 Flutter 更新为“中级独立开发”：

- 能脱离整页生成完成登录、列表、详情、上传等常规模块；
- 能解释 Widget、Element、状态、生命周期和异步更新链路；
- 能设计清晰的状态流、模块边界和依赖方向；
- 能处理网络、缓存、权限、构建、桥接和发布的常见问题；
- 能使用日志、测试和 DevTools 提供问题定位证据；
- 至少完成一次 Android 原生桥接和一次双端 Release 构建；
- 每个领域都有代码、测试、日志、截图、构建产物或案例中的至少一种证据；
- 能审查、解释并局部重写 AI 生成代码。
