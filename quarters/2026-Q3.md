# 2026 Q3：建立系统与第一批证据

## 季度目标

剩余周期不追求大而全，只完成以下可验证成果：

- [ ] GitHub + Obsidian 工作流稳定运行至少 4 周。
- [ ] 完成 2 个 Android 深度案例：页面卡顿与冷启动。
- [ ] Flutter 完成 01～03 核心学习、引导实验与登录垂直切片。
- [ ] Flutter 登录至少包含加载、错误、超时和重试状态。
- [ ] 建立 React Native 学习入口与项目骨架，为下一 Sprint 主攻做准备。
- [ ] 项目索引中补齐实际代码仓库链接。
- [ ] 完成 Q3 复盘，调整 Q4 的 iOS、HarmonyOS、Vue 与 Java 进入顺序。

## 本季度不做

- 不同时展开 iOS、HarmonyOS、Vue 和 Java 的完整学习。
- 不追求 Flutter 或 RN 的高级底层源码。
- 不堆积没有业务场景的纯理论笔记。
- 不把 AI 生成成功当作独立开发证据。

## 验收问题

季度结束时，必须能回答：

1. Android 卡顿和启动问题分别使用了什么证据定位？
2. Dart 与 Kotlin 在类型、空安全和异步语义上有哪些关键差异？
3. Flutter Widget、状态和生命周期如何共同完成一次登录状态更新？
4. 哪些代码可以脱离 AI 独立重建，哪些部分仍无法解释或排查？
5. 下一季度如何在不跳过 Flutter 04～08 的同时启动 RN 主攻 Sprint？

Flutter 与 React Native 的长期优先级不变。本季度先补齐 Flutter 零基础门禁，下一 Sprint 再切换 RN 主攻，避免两套陌生框架同时展开。
