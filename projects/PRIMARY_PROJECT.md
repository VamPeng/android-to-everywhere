# Everywhere Lab

## 目的

使用同一套业务模型，在 Android、Flutter、RN、iOS、HarmonyOS、Vue 和 Java 中反复实现，验证能力迁移，而不是分别学习互不关联的 Demo。

## 最小产品链

```text
登录
→ 内容/会话列表
→ 详情
→ 图片选择与上传
→ 本地缓存
→ 错误与重试
→ SSE AI 流式会话
→ 日志与问题反馈
```

## 各端职责

| 端 | 核心职责 |
|---|---|
| Android | 先验证复杂业务边界，并承载性能与疑难问题实验 |
| Flutter | 完整复制移动端垂直链路，达到中级独立开发 |
| React Native | 完整复制移动端垂直链路，达到中级独立开发 |
| iOS | 完成基础移动端链路，掌握语言与系统 API |
| HarmonyOS | 完成基础移动端链路，掌握语言与系统 API |
| Vue | 用户、内容、会话、配置与日志管理 |
| Java | 鉴权、数据、文件、AI 流式接口与统一日志 |

## 设计约束

- 各端共享接口契约与领域术语，但不强行共享全部代码。
- 每个平台保留符合自身生态的架构与状态管理方式。
- 先实现真实错误、取消、重试和空状态，再扩充页面数量。
- 关键功能必须有测试或可重复验证步骤。
- 所有日志、截图和数据必须脱敏。
